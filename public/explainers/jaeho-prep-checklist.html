Hostinger VPS에 개인 Agent를 만들고,
Telegram과 Obsidian Wiki를 연결하기

목표는 로컬 모델을 돌리는 것이 아니라, 로컬 PC/Obsidian에 지식 DB를 쌓고 VPS의 Agent가 Telegram을 통해 그 Wiki를 읽고 쓰게 만드는 것입니다.

용어 정리: 여기서 “로컬 LLM Wiki”는 Gemma 같은 로컬 LLM 모델이 아닙니다. 장재호님 PC의 Obsidian Markdown vault/wiki DB를 뜻합니다.

Sync choice

동기화 추천

1순위: Syncthing

무료, 오픈소스, 파일 그대로 동기화. 다만 초기 설정이 조금 필요하고 PC가 켜져 있어야 최신 상태가 됩니다.

2순위: Obsidian Sync

가장 편합니다. 유료지만 설정이 쉽고 모바일/PC 연동이 깔끔합니다.

3순위: GitHub Private Repo

버전관리는 좋지만 일반 사용자에게는 git 충돌/커밋 관리가 번거로울 수 있습니다.

Build sequence

진행 순서

1

VPS 만들기

Hostinger에서 Ubuntu VPS 생성. IP 주소와 SSH 접속 정보를 확보합니다.

2

서버 기본 보안

업데이트, sudo user, SSH key, 방화벽, fail2ban 정도만 먼저 설정합니다.

3

Hermes Agent 설치

VPS에 Hermes 설치 후 CLI에서 간단한 질문이 작동하는지 확인합니다.

4

Telegram Bot 연결

BotFather token과 장재호님 user ID를 넣고 Hermes gateway를 서비스로 실행합니다.

5

Wiki Vault 만들기

VPS와 로컬 PC 양쪽에 같은 Markdown vault를 만들고 동기화를 붙입니다.

6

첫 ingest 테스트

공개 기사 링크 1개를 Telegram으로 보내고 raw 저장, 요약 page, index/log 업데이트를 확인합니다.

Security policy

초기 보안 원칙

  • ✓
    공개자료만 1차 파일럿
    보도자료, 공개 기사, 공개 법령/가이드.
  • !
    회사 내부자료는 초기 금지
    계약서, 내부 이메일, 법무 의견, HR/노무 민감자료.
  • ✓
    Telegram 사용자는 allowlist
    장재호님 Telegram ID만 허용.
  • ✓
    API key는 VPS .env에만 저장
    채팅방/노트/스크린샷에 노출 금지.

First success test

첫 성공 기준

아래 5개가 되면 1차 구축은 성공입니다.

  1. 장재호님이 Telegram에서 개인 Agent에게 메시지를 보낼 수 있다.
  2. Agent가 공개 기사 링크를 읽고 요약한다.
  3. 원문이 raw/articles/에 저장된다.
  4. 관련 Wiki page가 생성/업데이트된다.
  5. 장재호님 PC의 Obsidian에서 그 page가 보인다.

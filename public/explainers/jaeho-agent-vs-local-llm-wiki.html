What is an Agent?

Agent는 “오늘 할 일”을 처리합니다

일반 챗봇보다 한 단계 더 나아가, 도구를 호출하고 여러 단계를 진행하며 결과물을 만듭니다.

  • 자료 조사 → 요약 → 비교 → 초안 작성
  • 문서/이메일/계약서 검토 보조
  • 웹사이트, 파일, 캘린더, 업무 시스템과 연결
  • 반복 업무를 체크리스트처럼 수행
Limitation

하지만 Agent는 기본적으로 “휘발성”입니다

대화가 길어지거나 세션이 바뀌면 맥락이 사라질 수 있습니다. 그래서 중요한 판단과 출처를 별도 지식 저장소에 남겨야 합니다.

Agent만 쓸 때 생기는 문제

같은 설명을 반복해야 하고, 과거 판단 근거를 찾기 어렵고, 여러 문서를 연결한 장기 맥락이 약해집니다.

What is Local LLM Wiki?

Local LLM Wiki는 “쌓이는 기억”입니다

Karpathy식 LLM Wiki는 자료를 단순 저장하는 폴더가 아니라, 서로 연결된 Markdown 지식망입니다.

  • raw/: 원문 보관 — 기사, PDF, 메모, 회의록
  • entities/: 회사, 기관, 인물, 법령, 프로젝트
  • concepts/: 개념 설명 — 세액공제, 공급망, 규제
  • comparisons/: 비교 — A안 vs B안, 주별 규제 비교
Why local?

“Local”의 의미는 통제권입니다

자료가 내 컴퓨터/내 서버의 파일로 남기 때문에, 특정 앱이나 LLM 서비스에 종속되지 않습니다.

장점

Markdown이라 Obsidian, VS Code, GitHub, Syncthing으로 열 수 있습니다. LLM이 바뀌어도 지식 파일은 그대로 남습니다.

가장 좋은 구조: Agent가 Wiki를 읽고 쓰는 구조

1. 원문/업무 질문기사, 계약서, 법령, 이메일, 회의 메모, “이 이슈 정리해줘” 같은 질문
→
2. Agent가 처리요약, 비교, 리스크 체크, 초안 작성, 빠진 정보 질문, 관련 페이지 검색
→
3. Local LLM Wiki에 축적출처가 붙은 Markdown 페이지로 저장. 다음 질문 때 다시 읽고 더 똑똑해짐

예: “Georgia EV tax incentive 관련 새 기사 추가해줘” → Agent가 원문 저장 → tax incentive 페이지 업데이트 → 현대차/LG JV 페이지와 연결 → 다음 질문 때 근거로 사용.

Recommendation

장재호님께는 이렇게 설명하고 시작하면 됩니다

  1. Agent는 매일 쓰는 업무 파트너 — 질문하고, 초안 만들고, 자료를 정리합니다.
  2. Local LLM Wiki는 장기 지식 창고 — 중요한 자료와 판단을 내 컴퓨터/서버에 Markdown으로 보관합니다.
  3. 처음 2주 목표는 “큰 시스템 구축”이 아니라 습관 만들기 — 좋은 원문 5개, 핵심 페이지 10개, 질문 10개부터 시작합니다.
  4. 보안/기밀 자료는 별도 규칙 필요 — 외부 LLM에 넣어도 되는 자료와 로컬에만 둘 자료를 구분합니다.
추천 첫 주제: “Hyundai–LGES Georgia battery JV / Savannah EV ecosystem / US manufacturing legal issues / LLM for lawyers” 네 축으로 시작.
FAQ

자주 헷갈리는 질문

Q1. Local LLM Wiki가 있으면 Agent는 필요 없나요?

아닙니다. Wiki는 지식 저장소이고, Agent는 그 지식을 사용해서 실제 일을 처리하는 실행자입니다.

Q2. 그냥 ChatGPT 대화 저장하면 안 되나요?

대화 저장은 시간순 기록입니다. LLM Wiki는 회사/개념/쟁점별로 재정리되고 서로 링크됩니다. 나중에 다시 쓰기 훨씬 좋습니다.

Q3. 꼭 로컬 LLM을 돌려야 하나요?

처음부터 꼭 필요하지 않습니다. 먼저 Markdown Wiki를 만들고, Agent가 정리하게 한 뒤, 기밀성과 비용 요구가 커질 때 로컬 LLM을 붙이면 됩니다.

Q4. 변호사 업무에서 가장 큰 장점은?

반복되는 쟁점, 고객/회사 맥락, 규제 변화, 과거 판단 근거가 축적됩니다. 새 이슈를 볼 때 “처음부터 다시 조사”하지 않아도 됩니다.
